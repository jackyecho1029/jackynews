# 群对话材料模板 (Group Dialogue Template)

## 💬 对话收集框架

### 对话类型分类

#### 1. 需求探索型对话
**目标：** 理解用户真实需求，而非表面诉求

**对话模式：**
```
用户：我需要一个自动化工具。
Agent：能描述一下你最近一次手动做这件事的场景吗？

用户：上周我花了 3 小时整理数据...
Agent：这 3 小时具体在做什么？哪个环节最耗时？

用户：主要是复制粘贴，然后检查格式...
Agent：如果有魔法棒，你希望这个过程变成什么样？
```

**关键技巧：**
- ✅ 用"描述场景"代替"你需要什么"
- ✅ 追问"具体是什么情况"
- ✅ 引导用户说出痛点而非解决方案

---

#### 2. 痛点挖掘型对话
**目标：** 识别核心问题和影响程度

**对话模式：**
```
Agent：这个问题多久发生一次？
用户：几乎每天都要处理。

Agent：每次大概花多长时间？
用户：少则 30 分钟，多则 2 小时。

Agent：如果不解决，会有什么影响？
用户：会延误项目进度，团队成员也会抱怨。

Agent：之前尝试过什么解决方案吗？
用户：试过 Excel 宏，但总是出错...
```

**提取要素：**
- 频率：[每天/每周/每月]
- 时间成本：[具体小时数]
- 影响范围：[个人/团队/公司]
- 失败尝试：[之前的解决方案]

---

#### 3. 方案验证型对话
**目标：** 确认提议的解决方案是否符合预期

**对话模式：**
```
Agent：我理解你的需求是 [总结痛点]，对吗？
用户：对，就是这个意思。

Agent：我建议的方案是 [简述方案]，你觉得怎么样？
用户：听起来不错，但能处理 [特殊情况] 吗？

Agent：可以，具体做法是 [解释细节]。
用户：那太好了！什么时候能开始用？

Agent：预计 [时间]，需要你提供 [资源/信息]。
```

**验证清单：**
- [ ] 用户确认痛点理解正确
- [ ] 用户认可解决方案方向
- [ ] 识别出潜在的边界情况
- [ ] 明确下一步行动

## 🎭 风格化对话示例

### 示例 1：技术型用户

```markdown
**场景：** 开发者需要自动化代码审查

用户：我们团队每次 PR 都要手动检查代码规范，太浪费时间了。

Agent：能具体说说检查哪些规范吗？比如最近一次 PR。

用户：主要是变量命名、注释完整性、还有是否遵循了我们的架构模式。上次有个 PR 改了 50 个文件，我看了 2 小时。

Agent：2 小时里，有多少时间是在做重复性检查？

用户：至少 80%，就是对照 checklist 一项项看。

Agent：如果有个工具能自动跑这些检查，生成报告，你只需要看不符合的部分，能节省多少时间？

用户：那至少能省 1.5 小时！而且不会漏掉。

Agent：明白了。那你希望这个工具集成到哪个环节？提交 PR 时自动跑，还是手动触发？

用户：最好是提交 PR 时自动跑，然后在评论区显示结果。
```

**提取的关键信息：**
- 痛点：手动代码审查耗时（2 小时/次）
- 重复性工作占比：80%
- 期望节省时间：1.5 小时
- 集成方式：PR 提交时自动触发
- 输出形式：评论区显示结果

---

### 示例 2：非技术型用户

```markdown
**场景：** 内容创作者需要素材管理工具

用户：我每次写文章都要翻半天笔记，找灵感太难了。

Agent：你的笔记都存在哪里？

用户：有的在 Notion，有的在微信收藏，还有些在手机备忘录...

Agent：那你找灵感的时候，一般要翻多久？

用户：快的话 20 分钟，慢的话 1 小时，有时候还找不到。

Agent：找不到的时候怎么办？

用户：就只能凭记忆写，或者放弃这个选题。

Agent：如果有个工具能把你所有笔记集中起来，按主题自动分类，还能搜索关键词，会有帮助吗？

用户：那太好了！最好还能提醒我哪些想法还没用过。

Agent：好的，那你平均一周写几篇文章？需要找多少次灵感？

用户：一周 3 篇，每篇都要找，所以一周至少 3 次。
```

**提取的关键信息：**
- 痛点：笔记分散，查找困难（20-60 分钟/次）
- 笔记来源：Notion + 微信 + 手机备忘录
- 使用频率：每周 3 次
- 期望功能：集中管理 + 自动分类 + 关键词搜索 + 使用提醒
- 失败场景：找不到时放弃选题

### 示例 3：团队协作场景

```markdown
**场景：** 项目经理需要团队协作工具

PM：我们团队现在用 Slack + Trello + Google Docs，信息太分散了。

Agent：能描述一下你最近一次因为信息分散导致的问题吗？

PM：上周有个需求，设计师在 Figma 改了，但开发不知道，结果做了旧版本。

Agent：这种情况多久发生一次？

PM：几乎每周都有，不一定是设计，有时候是需求变更没同步。

Agent：每次发现问题后，你们怎么处理？

PM：开会对齐，然后返工。一次至少浪费半天。

Agent：如果有个中心化的工作台，所有更新都能实时同步，还能 @ 相关人员，会改善这个问题吗？

PM：会！但关键是要简单，不能比现在更复杂。

Agent：明白。那你们团队有多少人？主要用什么设备工作？

PM：10 个人，都是电脑为主，偶尔手机看消息。
```

**提取的关键信息：**
- 痛点：工具分散导致信息不同步（每周 1 次）
- 影响：返工，浪费半天时间
- 团队规模：10 人
- 主要设备：电脑（偶尔手机）
- 核心需求：中心化 + 实时同步 + 简单易用
- 关键约束：不能比现状更复杂

## 🎯 对话质量评估

### 优秀对话的特征
- ✅ 包含具体的场景描述（而非抽象需求）
- ✅ 有量化的数据（时间、频率、影响范围）
- ✅ 捕捉到用户的原话（而非转述）
- ✅ 识别出隐藏的痛点（用户没直接说的）
- ✅ 明确了下一步行动

### 需要改进的对话
- ❌ 只有用户的需求列表，没有场景
- ❌ 缺少量化数据，都是"经常"、"很多"
- ❌ 过度转述，丢失了用户的表达风格
- ❌ 停留在表面问题，没有深挖
- ❌ 对话结束后不知道该做什么

## 🔧 对话技巧工具箱

### 开放式问题库
1. "能描述一下最近一次遇到这个问题的场景吗？"
2. "这个问题给你/团队带来了什么影响？"
3. "如果有魔法棒，你希望这个过程变成什么样？"
4. "之前尝试过什么解决方案？为什么没有坚持用？"
5. "还有其他人也遇到类似问题吗？他们怎么处理的？"

### 追问技巧
- **量化追问：** "具体是多长时间？" "大概多少次？"
- **场景追问：** "能举个具体例子吗？" "上次是什么时候？"
- **影响追问：** "如果不解决会怎样？" "对业务有什么影响？"
- **对比追问：** "和之前的方案比，有什么不同？"

### 确认技巧
- **总结确认：** "我理解你的意思是 [总结]，对吗？"
- **优先级确认：** "这个问题在你的优先级列表里排第几？"
- **可行性确认：** "如果方案是 [X]，你能接受吗？"

## 💡 最佳实践

### 对话前准备
1. 明确对话目标（探索需求/挖掘痛点/验证方案）
2. 准备 3-5 个核心问题
3. 预留足够时间（至少 30 分钟）

### 对话中注意
1. 多听少说（80/20 原则）
2. 记录用户原话（不要过度转述）
3. 适时追问（不要满足于表面答案）
4. 保持好奇心（探索"为什么"）

### 对话后整理
1. 立即整理笔记（趁记忆新鲜）
2. 提取关键信息（痛点、数据、期望）
3. 识别下一步行动
4. 归档到材料库

---

**使用提示：** 群对话材料是理解用户真实需求的关键，务必保留用户的原话和具体场景，避免过度抽象化。
